Pokeplan Star Schema

How the PokeAPI data is arranged in the database so it is easy to ask questions of it.

Fact table: things that happen or link together
Dimension: the details you filter and group by

The idea in three sentences

A star schema puts one fact table in the middle and connects it to dimension tables around it, so a diagram of it looks like a star.

The grain is a plain sentence saying what one row of a table means. You decide it before choosing any columns, and every row must match it.

A good test of the grain: if two rows describe exactly the same thing, the grain is wrong or the data has a duplicate.

Why time matters here

The Pokémon games span 30 years, and the rules changed along the way. A move, a Pokémon's stats or a type matchup can be different in Red/Blue and in Scarlet/Violet.

So several tables say when a row was true: either a range of generations (I to IX), or, for moves, a range of games. To ask "what was it like in generation 3?", you keep the rows whose range includes 3.

The Pokémon Domain Guide explains the game rules behind each choice.

The __NDIM__ dimensions

Each dimension describes one kind of thing, one row per thing. Several fact tables share the same dimension, so dim_pokemon means the same in every star. Two small bridge tables link a game to its regions and to its Pokédexes, because one game can have several of each.

How data gets there

1. Raw. Each API response is saved exactly as received.

2. Reference. A few small tables hold game knowledge the API doesn't have, such as when abilities were introduced and which games are remakes.

3. Staging. Views unpack the nested JSON into flat rows, one view per grain, and turn the API's history fields into date ranges.

4. Star. A load step fills the dimensions and facts above. Running it twice gives the same result.

Tested on the full real dataset (13,671 API responses, taken from PokeAPI's published copy on GitHub because the live site is blocked here). The load takes about 40 seconds and every test passes. The SQL is in the project folder under pokeapi/schema/, with a README giving the order to run the files.
