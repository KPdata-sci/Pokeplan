Pokeplan Terraform

The code that would build the Pokeplan on AWS architecture. Pick a part below; each one says what it builds in plain English, then shows the important lines with an explanation beside them.

Start here

Terraform files describe the AWS resources you want. terraform plan compares that description with what exists and lists the changes; terraform apply makes them.

How to read one block

example
resource "aws_s3_bucket" "raw" {
  bucket = "pokeplan-prod-raw"
}

module "storage" {
  source         = "../modules/storage"
  s3_endpoint_id = module.network.s3_endpoint_id
}
resource "type" "name"
One thing to create. The first word is the AWS type (here an S3 bucket); the second is the name the code uses for it.
bucket = "..."
A setting on that thing.
module
A folder of resources used like a function: inputs go in, outputs come out.
var.x / module.a.y
An input to this module / an output of module a.
for_each
Make one copy per item in a list or map, such as one subnet per zone.

Network

The private network everything else runs inside, and the only ways in and out of it.

Folder: terraform/modules/network/

What it builds

  • A VPC (10.40.0.0/16) spread over two availability zones.
  • Five kinds of subnet per zone: public (load balancer), egress (NAT), app (containers), data (database, no way out), firewall.
  • In prod, all outbound traffic passes Network Firewall, which only lets pokeapi.co and github.com through. The learning layout uses a cheaper DNS filter instead.
  • Private connections to AWS services (S3, Athena, SQS and others), so that traffic never touches the internet.
  • Flow logs of every connection.

The key code, explained

modules/network/main.tf
resource "aws_subnet" "app" {for_each          = local.az_indexvpc_id            = aws_vpc.this.idavailability_zone = each.keycidr_block        = cidrsubnet(var.cidr, 8, 10 + each.value)}

One private subnet per availability zone for the containers. for_each repeats the block for each zone, and cidrsubnet cuts 10.40.10.0/24 and 10.40.11.0/24 out of the VPC range. The other four subnet kinds are the same block with different numbers.

modules/network/main.tf
resource "aws_route" "app_default" {for_each               = local.az_indexroute_table_id         = aws_route_table.app[each.key].iddestination_cidr_block = "0.0.0.0/0"vpc_endpoint_id        = var.enable_network_firewall ? local.firewall_endpoints[each.key] : nullnat_gateway_id         = var.enable_network_firewall ? null : aws_nat_gateway.this[local.nat_for[each.key]].id}

Where the containers send internet traffic. In prod it goes to the firewall first, then NAT. In the learning layout it goes straight to NAT. The condition ? a : b form picks one based on the switch, and null means "leave this unset".

modules/network/firewall.tf
rules_source_list {generated_rules_type = "ALLOWLIST"target_types         = ["TLS_SNI", "HTTP_HOST"]targets              = var.egress_domains}​# from the firewall policy:stateful_default_actions = ["aws:drop_established", "aws:alert_established"]

The allowlist. A connection is let out only if the website name it asks for is on egress_domains (pokeapi.co, github.com and their subdomains). Everything else is dropped and written to the alert log.

Storage

Where the data lives: S3 buckets for the lakehouse, and the catalogue Athena uses to find tables.

Folder: terraform/modules/storage/

What it builds

  • Three buckets: raw (what dlt lands), lake (dbt's staging and mart tables), athena (query results, deleted after 30 days).
  • A separate KMS encryption key for each bucket, rotated yearly.
  • Public access blocked, versioning on, old versions kept 90 days so a bad load can be rolled back.
  • Three Glue databases matching the star schema layers: raw, staging, mart.
  • An Athena workgroup with a 10 GiB per-query limit as a cost guard.

The key code, explained

modules/storage/main.tf
resource "aws_s3_bucket_server_side_encryption_configuration" "this" {for_each = aws_s3_bucket.thisbucket   = each.value.idrule {apply_server_side_encryption_by_default {sse_algorithm     = "aws:kms"kms_master_key_id = aws_kms_key.this[each.key].arn}bucket_key_enabled = true}}

Every object in every bucket is encrypted with that bucket's own key. Looping over aws_s3_bucket.this means a new bucket added later gets this automatically.

modules/storage/main.tf
statement {sid       = "DenyWritesOutsideVpc"effect    = "Deny"actions   = ["s3:PutObject", "s3:DeleteObject"]  # ... resources and principals trimmedcondition {test     = "StringNotEqualsIfExists"variable = "aws:SourceVpce"values   = [var.s3_endpoint_id]}condition {test     = "ForAllValues:StringNotEquals"variable = "aws:CalledVia"values   = ["athena.amazonaws.com"]}}

Part of the bucket policy. It refuses any write that did not arrive through the VPC's private S3 connection, unless Athena is writing on dbt's behalf. Even a leaked AWS key used from a laptop cannot change the data.

modules/storage/main.tf
resource "aws_glue_catalog_database" "this" {for_each     = { raw = "raw", staging = "lake", mart = "lake" }name         = "${replace(var.name, "-", "_")}_${each.key}"location_uri = "s3://${aws_s3_bucket.this[each.value].bucket}/${each.key}/"}

The three schema layers as Glue databases: pokeplan_prod_raw in the raw bucket, and staging and mart in the lake bucket. Terraform makes only the databases; dlt and dbt create the tables inside them.

Events

What makes the pipeline event-driven: a bus, rules that route each event, and the nightly trigger.

Folder: terraform/modules/events/

What it builds

  • An EventBridge bus called pokeplan-prod, with every event archived for 30 days so a day can be replayed.
  • ingest.requested and raw.landed are routed to two SQS queues that Dagster watches.
  • quality.failed, run.failed and anything stuck in a dead-letter queue go to an alerts topic (email or Slack).
  • A nightly 02:00 London schedule runs a small Lambda that reads the latest PokeAPI/api-data commit and publishes ingest.requested.

The key code, explained

modules/events/main.tf
locals {queues = {ingest    = "ingest.requested"transform = "raw.landed"}}​resource "aws_cloudwatch_event_rule" "queue" {for_each       = local.queuesname           = "${var.name}-${each.key}"event_bus_name = aws_cloudwatch_event_bus.this.nameevent_pattern = jsonencode({source        = [local.source]"detail-type" = [each.value]})}

The routing table. Each line in queues becomes a rule: "when an event of this type arrives on the bus, send it to this queue". Adding a new event type means adding one line here.

modules/events/main.tf
resource "aws_sqs_queue" "this" {for_each                   = local.queuesname                       = "${var.name}-${each.key}"visibility_timeout_seconds = 300  # ... retention and encryption trimmedredrive_policy = jsonencode({deadLetterTargetArn = aws_sqs_queue.dlq[each.key].arnmaxReceiveCount     = 3})}

The two queues Dagster reads. If a message fails three times it moves to a dead-letter queue instead of retrying forever, and an alarm fires when that happens.

modules/events/trigger.tf
resource "aws_scheduler_schedule" "nightly" {name                         = "${var.name}-nightly"schedule_expression          = var.schedule          # cron(0 2 * * ? *)schedule_expression_timezone = var.schedule_timezone # Europe/London  # ... flexible_time_window trimmedtarget {arn      = aws_lambda_function.check_commit.arnrole_arn = aws_iam_role.scheduler.arn}}

Every night at 02:00 UK time, run the commit-check Lambda. It publishes the commit ID, and Dagster skips commits it has already loaded, so a quiet night costs nothing.

Permissions

Who may do what. Each job gets its own role with only the access it needs.

Folder: terraform/modules/iam/

What it builds

  • ingest (dlt): write the raw bucket and raw tables, nothing else.
  • transform (Soda and dbt): read raw, write staging and mart.
  • dagster: read the two queues and start the ingest and transform tasks.
  • metabase: read the mart tables through Athena.
  • A deploy role that GitHub Actions can use from the main branch only, with no AWS keys stored anywhere.

The key code, explained

modules/iam/main.tf
# ingest rolestatement {sid       = "RawBucketReadWrite"actions   = ["s3:GetObject", "s3:PutObject", "s3:DeleteObject", "s3:ListBucket", "s3:GetBucketLocation"]resources = [var.bucket_arns["raw"], "${var.bucket_arns["raw"]}/*"]}

The dlt job can read and write the raw bucket and nothing else. A bug in ingest cannot damage the marts.

modules/iam/main.tf
# dagster rolestatement {sid       = "PassOnlyPipelineRoles"actions   = ["iam:PassRole"]resources = [aws_iam_role.ingest.arn, aws_iam_role.transform.arn, aws_iam_role.execution.arn]}

Dagster starts tasks and gives each one a role. This limits it to the two pipeline roles, so Dagster cannot start a task with more power than those.

modules/iam/main.tf
condition {test     = "StringLike"variable = "token.actions.githubusercontent.com:sub"values   = ["repo:${var.github_repo}:ref:refs/heads/main", "repo:${var.github_repo}:environment:prod"]}

GitHub Actions signs in with a short-lived token instead of stored keys. This condition only accepts tokens from the main branch or the protected prod environment of your repository.

Governance

A second lock on the data. IAM says a role may use Athena; Lake Formation says which tables it may see.

Folder: terraform/modules/governance/

What it builds

  • Names the Lake Formation administrators.
  • Registers the raw and lake buckets so Lake Formation controls access to them.
  • Grants each role access to whole databases: write for the jobs that build them, read-only for the jobs and people that use them.

The key code, explained

modules/governance/main.tf
writers = {ingest_raw        = { role = var.task_role_arns["ingest"], db = local.db["raw"], location = "raw" }transform_staging = { role = var.task_role_arns["transform"], db = local.db["staging"], location = "lake" }transform_mart    = { role = var.task_role_arns["transform"], db = local.db["mart"], location = "lake" }}

The whole access model in three lines: which role writes which layer. The readers list next to it works the same way: transform reads raw, and Metabase and analysts read mart.

modules/governance/main.tf
resource "aws_lakeformation_permissions" "reader_tables" {for_each    = local.readersprincipal   = each.value.rolepermissions = ["SELECT", "DESCRIBE"]table {database_name = each.value.dbwildcard      = true}}

Turns each reader line into a grant: SELECT on every table in that database (wildcard = true), including tables dbt creates later.

Compute

The things that run: containers, the database behind Dagster and Metabase, and the front door.

Folder: terraform/modules/compute/

What it builds

  • An ECS cluster on Fargate (no servers to manage).
  • Long-running services: Dagster's web UI and scheduler, and Metabase.
  • Run-once task definitions for ingest (dlt) and transform (Soda and dbt), started by Dagster for each run.
  • Postgres 16 on RDS for Dagster's run history and Metabase's settings, in the data subnets.
  • A load balancer that makes everyone sign in before reaching Dagster or Metabase, with AWS WAF in front.

The key code, explained

modules/compute/alb.tf
action {type  = "authenticate-oidc"order = 1authenticate_oidc {issuer    = var.oidc.issuerclient_id = var.oidc.client_id    # ... endpoints and secret trimmed}}​action {type             = "forward"order            = 2target_group_arn = aws_lb_target_group.this[each.key].arn}

Two steps for every request to metabase.<domain> or dagster.<domain>. First, sign in with your identity provider. Only then is the request passed to the container.

modules/compute/ecs.tf
resource "aws_ecs_task_definition" "pipeline" {for_each      = { ingest = 1024, transform = 2048 }family        = "${var.name}-${each.key}"cpu           = each.valuememory        = each.value * 4task_role_arn = var.task_role_arns[each.key]  # ... image, logs and secrets trimmed}

One block, two task definitions. Ingest gets 1 vCPU and 4 GB, transform gets 2 vCPU and 8 GB, and each gets its own role from the permissions module.

modules/compute/database.tf
resource "aws_db_instance" "this" {engine                      = "postgres"engine_version              = "16"manage_master_user_password = truestorage_encrypted           = truemulti_az                    = var.db_multi_azpublicly_accessible         = falsedeletion_protection         = var.deletion_protection  # ... size, backups and logging trimmed}

The metadata database. AWS creates and rotates its password, so no password appears in the code. It is encrypted, unreachable from the internet, and has a standby copy in prod.

The stack

The one folder you run. It joins the modules together and picks the layout.

Folder: terraform/live/

What it builds

  • main.tf calls each module and passes one module's outputs into the next.
  • prod.tfvars and learning.tfvars hold the switches that make the two layouts.
  • tests/plan.tftest.hcl plans both layouts against a fake AWS, so the code is checked without an account.

The key code, explained

live/main.tf
module "iam" {source = "../modules/iam"​name                = local.namebucket_arns         = module.storage.bucket_arnskms_key_arns        = module.storage.kms_key_arnsglue_database_names = module.storage.glue_database_namesathena_workgroup    = module.storage.athena_workgroupbus_arn             = module.events.bus_arnqueue_arns          = module.events.queue_arnsgithub_repo         = var.github_repo}

How modules connect. module.storage.bucket_arns is an output of the storage module, handed to the permissions module as an input. Terraform works out the build order from these references.

live/learning.tfvars
environment             = "learning"az_count                = 2single_nat_gateway      = trueenable_network_firewall = falseinterface_endpoints     = []db_multi_az             = falsedeletion_protection     = false

The cheap layout is just different answers to the same questions. The prod file says the opposite for each line, so the two never drift apart.
